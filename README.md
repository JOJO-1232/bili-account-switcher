## 功能简介

B 站网页版的头像菜单里只有「退出登录」，切换账号需要重新扫码。本扩展通过保存与还原登录凭证，把多账号切换做成一次点击。

- **头像菜单入口**：在 B 站头像下拉菜单的「我的课程」后面插入「切换账号」，点击即打开面板。
- **工具栏弹出面板**：显示当前登录账号的头像、昵称与 UID，并提供「保存当前登录」「登录新账号」「刷新」。
- **一键切换**：在账号列表中点击任一卡片即切换，切换后**原有的 B 站标签页原地刷新**，不会额外新开标签页。
- **添加账号不丢当前登录**：开始添加前先完整备份当前登录态；新账号登录完成后自动入库，随时可切回，中途也可一键「恢复原账号」。
- **失败自动回滚**：切换前备份当前凭证，若目标凭证已过期或校验不通过，自动回滚到切换前的账号，不会把浏览器留在未登录状态。
- **凭证只在本机**：账号列表与登录凭证保存在浏览器本地 `chrome.storage.local`，不上传任何服务器，也没有任何后端服务。
- **界面**：液态玻璃风格面板，同时适配浅色与深色主题；状态框与账号卡片为直角，按钮、标签与头像保持圆润。

## 安装步骤

### 方式一：下载 Release 构建包（推荐）

1. 打开 [Releases 页面](https://github.com/JOJO-1232/bili-account-switcher/releases)，下载 `bili-account-switcher-v1.5.8.zip`。
2. 将 ZIP 解压到一个**长期保留的固定目录**。以「加载解压缩的扩展」方式安装时，浏览器读取的正是这个目录，之后请勿移动或删除它。
3. 打开扩展管理页并启用开发者模式：
   - **Edge**：地址栏输入 `edge://extensions` → 打开左下角「开发人员模式」→ 点击「加载解压缩的扩展」→ 选择第 2 步解压出的文件夹。
   - **Chrome**：地址栏输入 `chrome://extensions` → 打开右上角「开发者模式」→ 点击「加载已解压的扩展程序」→ 选择同一文件夹。
4. 建议把扩展图标固定到工具栏：点击工具栏的「扩展/拼图」图标 → 找到「B站账号切换器」→ 点击「固定」。

### 方式二：从源码加载

```bash
git clone https://github.com/JOJO-1232/bili-account-switcher.git
```

按方式一第 3 步，选择克隆下来的仓库根目录即可（根目录即包含 `manifest.json`）。

> **提示**：本扩展未上架任何应用商店，只能通过开发者模式加载。部分 Chromium 版本在重启时会提示「请停用开发人员模式扩展」，忽略即可，功能不受影响。
>
> **升级**：用新版本 ZIP 覆盖原解压目录，再到扩展管理页点击该扩展的「重新加载」。已保存的账号数据不会丢失。

## 使用方法

1. 打开任意 `bilibili.com` 页面，确认已登录。
2. 点击工具栏上的扩展图标，打开面板；顶部会显示**当前登录账号**。
3. 点击「保存当前登录」，把该账号加入列表。
4. 需要第二个账号时点击「登录新账号」：扩展会暂存当前登录态并打开 B 站登录页，完成登录后新账号自动加入列表。
5. 在列表中点击任一账号卡片即可切换；带「当前」标签的是正在使用的账号。
6. 点击卡片右侧「删除」可移除保存的记录——**仅删除本机的凭证快照，不会让该账号退出登录**。

### 为什么添加账号要先「摘下」当前登录

B 站的登录页（`passport.bilibili.com/login`）在已登录状态下会直接 302 跳回首页，根本不渲染二维码或密码表单。因此扩展先把当前账号的 4 个登录 Cookie 完整备份并暂存，清除登录 Cookie 后再打开登录页；新账号登录成功后自动入库，随时可以点卡片切回。若中途放弃，点击面板上的「恢复原账号」即可把原凭证原样写回。

### 切换失败会怎样

切换前会先备份当前凭证；若目标账号的凭证已过期，或写入后调用 B 站接口校验 UID 不一致，扩展会**自动回滚**到切换前的账号并提示凭证过期。此时重新登录该账号，再点一次「保存当前登录」即可。

## 工作原理

B 站网页版的登录态由 4 个 Cookie 承载：`SESSDATA`、`bili_jct`、`DedeUserID`、`DedeUserID__ckMd5`。

- **保存**：调用 `api.bilibili.com/x/web-interface/nav` 读取当前账号的 UID / 昵称 / 头像，并快照上述 4 个 Cookie，存入 `chrome.storage.local`。
- **切换**：清除现有登录 Cookie → 写入目标账号的 Cookie 快照 → 校验当前登录 UID → 刷新原有的 B 站标签页；失败则回滚。
- **菜单入口**：content script 克隆头像菜单中「我的课程」的外层容器并替换文字，因此完整继承 B 站自身的类名、间距与 hover 样式，不依赖写死的 CSS 选择器。

实现细节可查阅仓库中的 [`background.js`](background.js)、[`content.js`](content.js) 与 [`accounts.js`](accounts.js)。

## 权限说明

扩展在 [`manifest.json`](manifest.json) 中声明的权限如下，除此之外**未声明任何其他权限**：

| 权限 | 用途 | 边界 |
| --- | --- | --- |
| `cookies` | 读取 / 写入 / 删除 `bilibili.com` 域下的 4 个登录 Cookie | 仅在保存、切换、添加账号时操作；不读取其他站点的 Cookie |
| `storage` | 用 `chrome.storage.local` 保存账号列表与凭证快照 | 数据仅存在本机浏览器内，不上传服务器、不经过任何后端 |
| `*://*.bilibili.com/*`（主机权限） | 注入头像菜单入口、查询并刷新 B 站标签页、请求 B 站 `nav` 接口获取登录信息 | 不读取或记录网页内容，不注入第三方脚本，不访问其他域名 |

补充说明：

- 扩展**没有**声明 `tabs`、`history`、`downloads`、`webRequest`、`clipboardRead` 等敏感权限。
- 不收集、不统计、不上报昵称、UID、Cookie、浏览记录或任何使用行为。
- 卸载扩展或清除该扩展的站点数据，即可删除本地保存的全部凭证。

## 隐私与安全

- 登录 Cookie 等同于账号登录态。**请勿把本机配置目录、`storage.local` 数据或包含凭证的文件分享给他人**；在公用或共享电脑上请谨慎使用。
- 本项目源码完全公开，建议在使用前自行审阅 `background.js` 中的 Cookie 处理逻辑。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 提示「当前浏览器未登录B站，请先登录」 | 先在 `bilibili.com` 完成登录，刷新页面后重试 |
| 提示「没有取到登录凭证（SESSDATA）」 | 刷新 B 站页面；仍失败则退出后重新登录再保存 |
| 切换后页面仍显示旧账号 | 等待原标签页刷新完成；若仍未更新，点击面板右上角的刷新按钮 |
| 头像菜单里没有「切换账号」 | 刷新 B 站页面；菜单需点击头像展开后该入口才会出现 |
| 提示「该账号的登录凭证可能已过期」 | 扩展已自动回滚；重新登录该账号并再保存一次 |
| 面板里的头像不显示 | 多为 B 站图床防盗链，属正常现象，不影响切换 |
| 升级后账号列表不见了 | 请确认加载的是原来的解压目录；更换目录会生成新的扩展 ID 与独立存储 |
